# GitHub Profile README Tone and Showcase

**Date:** 2026-08-09
**Status:** Approved for implementation

## Goal

Make Dmitrii's GitHub profile feel casual, honest, and human while keeping a clear sense of ambition. The README should communicate that he is still improving and trying to get where he wants to be, without presenting unfinished work as polished achievements.

## Design

The README keeps a small amount of visual structure—heading, badges, short sections, and one project callout—but replaces the portfolio-style project table with first-person writing.

### Voice

- Casual and conversational
- Honest about being early in the journey
- Ambitious through persistence and direction, not status claims
- Short sentences and natural wording
- No corporate portfolio language or inflated claims

### Content structure

1. **Opening:** Introduce Dmitrii in first person as someone building, learning, and trying to get better.
2. **What I am working on:** Explain the broad interests—AI, automation, systems, and experiments—without naming private projects.
3. **Open source:** Feature Hearsay as the current open-source project, with a plain-language description and link.
4. **Private work note:** Explicitly say that most other work is closed source, so it is not listed publicly.
5. **Toolbox:** Keep a compact set of technology badges as visual texture, without implying every tool is an active public project.
6. **Closing:** End with a warm, low-pressure line about learning, building, and getting there.

## Content boundaries

- Hearsay is the only named project showcase.
- Do not name or describe private repositories.
- Do not imply that the profile is a complete portfolio.
- Keep the existing public GitHub links and remove stale or unsupported project claims.
- Avoid adding external decorative services or links that are not verified.

## Acceptance criteria

- A visitor can understand Dmitrii's personality and direction within the first few lines.
- The README explicitly distinguishes Hearsay as the current open-source work.
- The README explicitly explains why other work is not shown.
- The writing sounds like a person speaking, not a marketing bio.
- The README remains readable and visually balanced on GitHub.
- The change is committed and pushed to `melonwer/melonwer` after verification.
